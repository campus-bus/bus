## 3. 重要口径和约束

### 3.1 线路命名口径

原图第一张标题为“三号院环线发车时刻表”，但最终统一命名为：

```text
环线1路
```

原因：与环线2路、环线3路命名方式保持一致，便于后续小程序和大模型处理。

### 3.2 日期类型口径

- 环线1路：工作日运行；周末/节假日不运行。
- 环线2路：有工作日时刻表，也有周末/节假日时刻表。
- 环线3路：有工作日时刻表，也有周末/节假日时刻表。

### 3.3 红字和打钩的含义

图片中出现两类特殊标识：

1. 红色字体：表示该车次从系统工程学院发车。
2. 手写打钩：也表示该车次从系统工程学院发车。

由于系统工程学院旁边对应站点是“高超楼”，最终表格中统一按以下口径处理：

```text
系统工程学院发车 = 高超楼发车
```

### 3.4 环线1路打钩车次的特殊路线

环线1路中打钩的车次虽然属于环线1路时刻表，但并不走普通环线1路路线。用户补充说明：这些车次处于就餐时间，实际走“就餐专线”路线。

因此最终表格中：

- 环线1路普通车次：走普通环线1路路线。
- 环线1路打钩车次：走就餐专线路线，且从高超楼发车。

需要特别注意：不要把环线1路打钩车次继续按普通环线1路预测到站。

## 5. 路线图与站点顺序

用户发送了一张环线路线图，其中包括环线1路、环线2路、环线3路的线路位置和途经站点。

用户补充的关键距离信息：

- 东门到北门的长度约 1.9 公里。
- 理学院到二食堂约 1 公里。
- 如果路线是“305教学楼 → 图书馆 → 2号宿舍楼 → 军体活动中心 → 水上训练中心 → 二食堂 → 5号宿舍楼 → 305教学楼”这一圈，大约 2 公里。
- 校园限速约 25 km/h。
- 用户不知道每个站点之间精确距离，也不知道具体到站时间，因此需要根据路线图、已知局部距离、校园限速、发车间隔进行合理预测。
- 一趟车从发车点走完整条线的时间不能超过下一次发车时刻，否则车辆无法周转。
- 到达发车点后应预留几分钟等待上车，不能按连续不停歇运行处理。

## 7. 最终 Excel 工作表使用说明

### 7.1 `结构化数据`

用途：

- 这是最适合后续程序读取的基础时刻数据表。
- 每一条发车记录应对应一行。

典型字段含义：

- 线路：环线1路、环线2路、环线3路。
- 日期类型：工作日、周末/节假日。
- 班次：第一班、第二班、第三班、第四班（夜1）、第五班（夜2）等。
- 发车时间：原始图片识别或用户确认的发车时刻。
- 发车地点：研究生宿舍楼或高超楼。
- 是否系统工程学院发车：是/否。
- 驾驶员：如刘虎、郭海燕、刘晓燕、孙五星、夏文新。
- 车号：如1号车、2号车、3号车、4号车、5号车。
- 备注：例如“推测待确认”“打钩，按高超楼发车”“红字，按高超楼发车”等。

程序开发建议：

- 小程序可优先读取此表作为发车计划主数据。
- 不建议直接从横向时刻表解析，因为横向表更适合人工查看。

### 7.2 `横向时刻表`

用途：

- 保留类似原始图片的横向时刻排列。
- 适合人工核对。

说明：

- 标注【系统】的时间表示高超楼发车。
- 工作日环线2路的 17:10、21:30 为用户根据发车间隔推测，后续如确认应更新备注。

### 7.3 `总览`

用途：

- 快速查看每条线路、每种日期类型下的发车数量、首末班、系统/高超楼发车数量。

注意：

- 环线1路仅工作日运行。
- 周末/节假日没有环线1路。

### 7.5 `路线站点与偏移`

用途：

### 7.11 `秒级路线参数_可调整`

这是后续校准最重要的工作表之一。

用途：

- 按线路/路线类型记录每一段站点之间的基准运行秒数。
- 提供可手动修改的秒级参数。

典型字段含义：

- 线路：环线1路、环线2路、环线3路。
- 日期类型：工作日、周末/节假日，或通用。
- 路线类型：普通路线、就餐专线、高超楼发车路线等。
- 站序：第几个站间段。
- 起点站：上一站。
- 终点站：下一站。
- 基准站间秒：初步根据路线图、距离、限速和发车间隔推测出的站间耗时。
- 手动采用秒：用户后续实测后可手动填写的实际采用值。
- 最终站间秒：若“手动采用秒”已填写，则使用手动值；否则使用基准站间秒。
- 累计秒：从发车站开始累计到当前站的秒数。

后续校准方法：

1. 用户实际乘车记录每一站到站时间。
2. 在 `实测记录模板` 中录入实测数据。
3. 计算每段站间实际秒数。
4. 将确认后的秒数填入 `秒级路线参数_可调整` 的“手动采用秒”。
5. `最终站间秒` 和 `累计秒` 会据此更新。
6. 预测到站明细随之更新。

### 7.12 `实测记录模板`

用途：

- 供用户实际坐车时记录每站到站时间。
- 帮助后续校准秒级站间运行时间。

建议实测记录字段：

- 日期
- 日期类型
- 线路
- 班次
- 发车时间
- 路线类型
- 车号
- 驾驶员
- 上一站
- 当前站
- 上一站实际到达时间
- 当前站实际到达时间
- 实测站间秒
- 是否拥堵/是否上下客较多
- 天气/备注

实测建议：

- 同一站间段最好记录多次。
- 早高峰、午餐、晚餐、夜间可能速度不同，后续可按时段进一步细分。
- 如果上下客明显较多，应在备注中标出，避免误把异常停靠时间当作常规运行时间。

### 7.13 `预测到站明细_秒级`

用途：

- 展示每一班车每一站的预计到站时间。
- 时间精确到 `hh:mm:ss`。

开发建议：

- 小程序中展示时可以按用户体验选择：
  - 内部计算使用秒级。
  - 前端展示可显示到分钟，或在临近到站时显示“约30秒后到达”。

### 7.14 `运转校验_秒级`

用途：

- 用秒级参数检查车辆周转是否合理。
- 判断一趟车完成路线后，到下一次同车发车之间是否有足够等待时间。

建议判断逻辑：

- 如果剩余等待时间为正，且大于预留等待阈值，则运转可行。
- 如果剩余等待时间过短，应提示需要人工复核站间秒数或车次归属。
- 如果剩余等待时间为负，说明预测路线耗时超过发车间隔，需要调整路线、站间秒或检查该车是否实际不是同一车辆连续运行。

### 7.15 `秒级总览`

用途：

- 汇总各路线的秒级全程预测结果。
- 展示首末班、发车数量、路线耗时等关键指标。

### 7.16 `秒级预测说明`

用途：

- 解释秒级预测如何得到。
- 说明哪些数据是原始时刻，哪些是预测。
- 指导后续如何通过实测数据校准。

## 8. 原始时刻数据与预测数据的区别

### 8.1 原始/确认数据

以下数据属于较高可信度数据：

- 图片中清楚显示的发车时间。
- 用户明确确认或修正的发车时间。
- 用户明确确认的驾驶员姓名。
- 用户明确说明的运行日期类型。
- 用户明确说明的红字/打钩含义。
- 用户明确说明的系统工程学院等同高超楼发车口径。
- 用户明确说明的环线1路打钩车次走就餐专线。

### 8.2 推测/待确认数据

以下数据应在表格中保留备注，后续需要实测或进一步确认：

- 工作日环线2路第一班最后一个时间 `17:10`：因原图右侧不完整，由用户根据发车间隔推测。
- 工作日环线2路第二班最后一个时间 `21:30`：因原图右侧不完整，由用户根据发车间隔推测。
- 所有预测到站时间。
- 所有站间运行秒数。
- 全程运行时间和车辆等待时间。

### 8.3 小程序展示建议

在没有实测校准前，建议小程序将到站时间展示为：

```text
预计到达
```

而不是：

```text

```

可以在页面底部补充说明：

```text
到站时间为根据路线和发车时刻估算，实际时间可能受上下客、道路情况和车辆调度影响。
```

### 11.1 用户实测时建议记录内容


### 11.2 如何更新 Excel

1. 打开 `实测记录模板`。
2. 填写每段站间的实际到达时间。
3. 查看自动计算出的实测站间秒。
4. 对同一站间段多次实测后，取一个合理值。
5. 把合理值填入 `秒级路线参数_可调整` 的“手动采用秒”。
6. 检查 `预测到站明细_秒级` 和 `运转校验_秒级` 是否更新合理。

### 11.3 实测值取值建议

如果同一段记录了多次：

- 可取中位数，减少偶然停车或上下客导致的极端值影响。
- 可分时段统计，例如早餐、午餐、晚餐、晚间。
- 如后续数据充足，可建立不同的路线参数版本。
