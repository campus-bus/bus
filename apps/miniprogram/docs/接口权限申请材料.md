## 〇、这次为什么被驳回，以及为什么改完能过

第一次提交时只上传了 1 张地图截图，驳回理由：
**「因你提供的申请原因/辅助图片/网页/视频内容无法确认申请接口使用场景审核不通过」**

> 一句话解释：一张静态图只能证明「地图上有个蓝点」。而**单次 `getLocation` + `<map show-location>` 也能画出那个蓝点**，
> 审核据此无法判断「为什么非要把位置持续开着不可」。所以这次要证明的不是「有定位」，而是
> **「这个页面上的位置和距离数字，会随着用户走路不停变化」**。

这次的材料由两部分组成：

1. **申请理由**（本文第一、二节，可直接粘贴，`startLocationUpdate` 与 `onLocationChange` 两段措辞不同，避免被判「重复机械提交」）；
2. **8 张连续截图**（本文第三节，同一地图页拍 5 帧），把「定位点前移 → 距离从 135 米变到 14 米」这个过程拍出来。

## 一、`wx.startLocationUpdate` 使用场景说明（提交文案）

> 后台"使用场景"输入框一般限 300 字符，用下面这段（约 210 字），直接粘贴。

```
用户打开「地图」页或首页「附近站点」查看自己与校园班车的位置关系时使用。校园环线班车不在站台等待，学生需要在步行去车站的路上持续看到自己的位置变化（定位点前移、距最近站点还剩多少米、还能不能赶上下一班），所以停留在这两个页面时开启前台位置更新。离开页面或小程序切到后台立即停止，不采集后台位置，不上传、不存储轨迹。
```

**要点对应（审核关注点）**

| 审核会问 | 本文回答 |
|---|---|
| 哪个页面 | 「地图」页（底部第 3 个 tab）与首页「附近站点」区块 |
| 谁触发 | 用户自己点开该页，不是启动即采集 |
| 为什么不能只取一次 | 位置在用户走路时一直在变，见第三节 3/8–7/8 |
| 什么时候停 | 离开页面 / 切后台，代码里已实现 `stopLocationUpdate` + `offLocationChange`；tab 切换用「所有权」机制，不受页面 `onShow`/`onHide` 先后顺序影响 |
| 有没有后台定位 | 没有，`app.json` 未配置 `requiredBackgroundModes` |

## 二、`wx.onLocationChange` 使用场景说明（提交文案）

> 与上一段**分开填写**，措辞要不同，重点讲"收到回调之后刷新了什么"。

```
用于在地图页接收前台位置变化并刷新界面：学生步行前往车站的过程中，位置回调会更新蓝色定位点，并实时刷新顶部的「距「激光所」135 米 · 步行约1分44秒」提示，用户据此判断继续走还是改去另一个站点。单次获取只能得到一个静止坐标，走起来后距离不再变化，无法支撑这个判断。仅前台监听，切后台即注销，位置只在本地渲染，不上传、不存储、不共享给第三方。
```
**两段文案的差异**（避免被判定为重复提交）：
- `startLocationUpdate` 讲「**什么时候开、什么时候关**」——会话生命周期；
- `onLocationChange` 讲「**收到回调后刷新了什么**」——定位点与实时距离数值。

## 五、提交步骤与注意事项

1. **两个接口分两次提交**（各自粘贴对应文案），驳回时才能定位到底是哪一个。
2. 图片上传顺序按 `1/8 → 8/8`，**不要打乱**，说明条上的序号就是为了让审核顺着看。
3. 若表单只能填 300 字符，用第一节/第二节的短版；若还有「补充说明」栏，可把第三节 3.2 的表格内容贴上。
4. 代码侧已满足（审核阶段会被校验）：
   - `manifest.json` → `mp-weixin.requiredPrivateInfos` 含 `getLocation`、`startLocationUpdate`、`onLocationChange`；
   - `permission.scope.userLocation.desc` 已写用途说明；
   - 用户隐私保护指引已声明「位置信息」用途。
5. 常见驳回与对策：

   | 驳回理由 | 对策 |
   |---|---|
   | 无法确认使用场景 | 补 3/8–7/8 这组连续图，并强调「同一页面、距离数值在变」 |
   | 使用场景描述过于笼统 | 写清「哪个页面、哪次点击、算出什么数值、给用户什么结论」 |
   | 类目不符合 | 类目须为「工具 → 信息查询」（`startLocationUpdate` 开放类目更窄） |
   | 判定重复提交 | 两段文案必须不同，见第二节末的差异说明 |

6. **万一还是不通过**：最稳的退路是放弃这两个接口，只保留已通过的 `wx.getLocation`。
   小程序没有"持续定位"后，地图页仍能通过 `<map show-location>` 显示蓝点（它由腾讯地图 SDK 自行绘制，不依赖 `onLocationChange`），
   只是顶部「距…米」不再实时刷新、定位按钮拿到的是进入页面那一刻的坐标。功能可用性影响很小。
